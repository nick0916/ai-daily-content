### 1. 點子的信心要看證據強度，不看意見
Confidence Meter 依證據分級：個人意見約 0.1/10、紙上審查約 0.5/10、蒐集資料最多 3/10，真正的測試與上線後數據才能拿更高分。套用時，為每個待辦點子標註目前的證據等級，低分者先做低成本驗證再投入開發。早期 fake-door 或可用性測試也可能產生假訊號，Gmail 案例就是通過後 A/B 結果仍很差。

### 2. Agent 會出錯，要設計成失敗後能續跑
Durable execution 讓 workflow 程式碼保持確定性，LLM 與 API 呼叫放進 activity 並記錄結果，worker 掛掉後從最後成功步驟接續，不重跑也不重花 token。重試是政策而非迴圈，人工核准可等待任意時間。涉及金流或狀態的流程，可由確定性 workflow 掌管，LLM 只做有界的建議。

### 3. 審查者與實作者要分離，用不同模型交叉驗證
實作 agent 的 context 已被除錯與探索佔用，且同一模型與 harness 有偏見，自己審自己容易漏看。把審查 agent 獨立出來，並用不同模型或對抗式審查者，結論一致視為高信號，差異大則需深入調查。也可在生成過程的 25%、50%、75% 觸發審查，及早導正偏離。
