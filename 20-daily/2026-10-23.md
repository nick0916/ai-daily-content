### 1. 沒有標準答案時，先植入答案再讓 agent 找回來
把已知答案或缺陷埋進資料（刪條款、改名稱、用模板生成案例），再用程式比對 agent 是否找回，就能不靠 LLM judge 自動評分。評估頻率因此可從每週一次提高到每天數十次。專家回饋應拿來改進測試，而不是直接改 agent。

_類型：technique_

### 2. 讓 AI 寫查詢，讓確定性引擎算數字
把工作拆成非確定性與確定性兩段：agent 只產生受限的 SQL 或 Python 並解讀結果，數字交給 DuckDB 這類引擎計算。這樣分析可重播、可稽核，適用於任何需要可驗證事實的分析場景。

### 3. 平均分數會掩蓋單項能力退化
評估模型優化（如 KV cache 量化或調整 reasoning effort）時，不能只看平均分數與中位數。KV cache 改為 4-bit 後平均幾乎持平，但單項下降 6.6 個百分點；併發 32 升到 64 時吞吐約 1.9 倍，P95 首 token 延遲卻明顯變長。應在自己的任務上逐項比較設定。

### 4. 用四個因素決定程式碼要寫多嚴謹
以失敗後果、替換成本、依賴程度、維護成本判斷軟體屬於拋棄式或長期維護型，全低則品質不重要，全高則很重要，不確定時偏向長期維護型。同時投資標準化、快速測試與最嚴格的 lint，降低嚴謹度的成本，即使判斷錯了也不貴。
