## Your Agent Hates Your CLI - Ayush Bhardwaj, Allos AI

看 agent 的 transcript 就知道你的 CLI 缺什麼：它們反覆自己寫的 pipe 就是 bug report。

**Why** agent 遇到不好用的輸出時不會回報問題，而是自己用 head、tail、grep、python 切輸出；這種切法暗含「答案在哪」的猜測，還可能因沒設 pipefail 而吞掉錯誤與錯誤碼。

**How** 分析 transcript 中 agent 呼叫工具後立刻做的事，找出重複出現的 pipe 模式，把它們變成 CLI 內建的選取 flag（範圍、限制、compact 輸出、一次查多筆），再用 skill 檔與 help 文字教 agent 使用；並以過去呼叫當 replay 測試案例。

**What** 講者 Ayush Bhardwaj（Allos AI）分析約 20,000 次 agent 呼叫：約四分之一帶 pipe，讀取類指令超過一半（git show、cargo test 皆 62%），83% 的 pipe 屬於至少出現 10 次的重複模式。他自己的 CLI 加入新 flag 後，pipe 比例從 82% 降到約四分之一；Infra 成本工具案例則是 6 題中從 0 題答對提升至 6 題全對，整體成本降 41%。

### 重點
- 20,000 次呼叫中約 25% 有 pipe；git show 與 cargo test 各 62%；83% 的 pipe 屬重複模式，可直接內建成 flag
- skill.md、help 文字、錯誤訊息即是介面：他把 flag 改成 no-op 但 skill 仍叫 agent 用，95 次搜尋仍照傳；改寫 skill 後兩個 session 都沒再傳
- agent mode：偵測 agent 呼叫後預設少輸出並提示取得更多的方式（如「顯示 20 / 300」＋offset），錯誤以 JSON 回傳；DuckDB 的類似做法減少約 59% 的輸出，但 token 僅降約 0.5%，要以回合數與答對率衡量
