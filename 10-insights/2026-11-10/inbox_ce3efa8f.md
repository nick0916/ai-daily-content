## Your PR Says the Tests Passed. Prove It. - Stephen Chin & Cassandra Chin

先用圖資料庫把證據整理好，再讓 AI 寫 PR 說明，寫得更準也更省 token。

**Why** AI 寫的 PR 常照 diff 逐行描述、事實有誤（例如謊稱測試通過），被審查者退回；反覆修訂與重建證據又很耗 token。

**How** 讓 Trace Tune 從本機 agent session 紀錄找出該分支的證據，再用嵌入式 Rust 圖資料庫 Relate 預先建好「鄰域摘要（neighborhood brief）」，把程式碼、檢查結果與來源關係串成一包；用較便宜的 Haiku 級模型當 reviewer 交叉檢查，但保留較高階的 Sonnet 級模型當 writer，因為低階模型寫出來太機械化。

**What** 講者 Stephen Chin 與 Cassandra Chin 介紹開源專案 Trace Tune（trace-tune.com）與新發布的 Relate 圖資料庫。依 PRBench 的 LLM judge 評分（1–100 分），Claude 與 Codex 都提升約 2–4 分（如 74→76、82→86）；講者表示 token 用量約降為原本的一半。

### 重點
- Relate 為開源、記憶體內、Rust 寫成的 agent 用嵌入式圖資料庫，建立證據圖不需 LLM 成本，僅耗本機運算
- 反直覺做法：writer 用高階模型（Sonnet/類似級別）、reviewer 用便宜的 Haiku 級，因為審查與交叉檢查較機械，而人味寫作需要強模型
- PRBench 評分在 Claude 與 Codex 上各提升約 2–4 分（74→76、82→86），token 約減半
