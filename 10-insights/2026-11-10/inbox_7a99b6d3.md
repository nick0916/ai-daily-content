## You Can't Tell What an Agent Skill Will Do by Reading It - Roey Ben Chaim, Zenity

光讀 agent skill 的文字看不出它會做什麼，要把它丟進沙盒真的跑一遍才知道。

**Why** skill 由他人撰寫，payload 常放在別處（外部連結、安裝腳本、套件下載），靜態掃描會漏掉；LLM 分析器也可能被一句假註解騙過。

**How** 借用惡意程式研究的「引爆室」做法：世界建構器依 skill 建出所需環境，operator 分析各條執行路徑並驅動 agent，再用對抗式 operator 突破 agent 的拒絕；同時收集 agent trace、行程建立、檔案系統與網路封包。

**What** Zenity 的 Roey Ben Chaim 說，用此方法在數千個 skill 中找出 100 個惡意 skill，已從 skills.sh 下架。案例包括假 Polymarket 套件（竊取資訊）、假冒 Paperclip 的帳號散播憑證竊取程式（相關 skill 下載量達 170 萬，通報 Vercel 與 Microsoft 後 12 小時內下架），以及持久化、靜默替換、遠端 prompt、hook 濫用等手法。

### 重點
- 靜態掃描失效的原因：skill.md 只是入口，payload 可藏在遠端 prompt、npm 安裝腳本、其他套件；Trail of Bits 研究顯示 LLM 分析器可被一句「團隊已核准」的註解騙過
- 引爆室結果：數千個 skill 中找出 100 個惡意，並追查到冒充 Paperclip 的憑證竊取活動（相關 skill 下載量 170 萬，已通報並於 12 小時內下架）
- 常見手法：寫入 soul/agent 檔的持久化指令、靜默卸載官方 skill 並以自己取代、遠端 prompt 執行、利用 user prompt submit 等 hook 每次觸發；建議把 skill 當套件依賴管理，限制權限並觀察實際行為
