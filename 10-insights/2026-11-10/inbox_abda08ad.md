## The Agents Were Fine. Everything Around Them Broke. - Joey Wang, Harvey

AI 寫程式不是難題，難的是把它產出的東西跑起來、檢查、並安全合併。

**Why** 雲端代理一多，真正壞掉的不是代理本身，而是周邊的 harness：容量、告警風暴、PR 合併。

**How** Harvey 的 Spectre 平台在底層執行 Claude Code、Codex、Cursor 等代理；規則是「人能點的，代理就能呼叫」，全面提供 CLI；用 follow-up loop 讀取 CI 失敗並自動追修；用公平排隊（fair launch queue）與重複告警合併解決容量問題。

**What** 平台累計 10,000 個 agent PR，上個月約 460 人使用，平均每分鐘就有一個代理啟動；8 月一個 bug 觸發約 900 個代理追同一問題，10 月一位工程師 3 小時內從 CLI 丟出約 950 個任務塞爆叢集；300 任務爆量負載測試下，任務啟動延遲從近 2 秒降到 70 毫秒。後端 agent PR 中五分之四經過 follow-up loop；PR 量單月成長約 60%，merge 從 15–30 分鐘變成超過 1 小時，講者表示 merge 瓶頸尚未解決。

### 重點
- Follow-up loop（讀 CI 失敗並自動推修）10 月起全面開啟，後端 agent PR 約 4/5 經過它；若只做一個階段就做這個
- 事故兩則：告警風暴使任務從日常約 50 個暴增到約 900 個；單人 CLI 丟約 950 任務塞滿叢集，4 天後上線公平排隊，300 任務爆量下延遲從近 2 秒降到 70 ms
- 自動化護欄：連續失敗 5 次自動關閉、可設預算或到期日；目前僅約 1/20 的 merge 附有「已證明可用」的證據
