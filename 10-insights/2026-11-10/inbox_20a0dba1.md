## Every Correction You Give Your Agent Is Data - Brian Douglas, Paper Compute

把你對 agent 的「糾正」當成訓練資料，讓 AI 學會替你把關自己不懂的領域。

**Why** 講者不會寫 Rust，卻靠 agent 產出 Rust 程式，PR 送審時被資深同事大量退回；而團隊越來越多在 CLI 內審查程式，反饋沒留在 GitHub 上。

**How** 用 Tapes 收集 agent session 並標註（如「pushback」＝工程師對 agent 的反駁，代表其擁有 agent 不知道的知識），再據此建立 skills、evals，並在 Qwen 4B 上做特化微調，做出模仿同事口吻審查 PR 的「Twin Review」。

**What** 講者 Brian Douglas（Paper Compute）以約 80,000 筆團隊 session 為資料來源，建議先寫 skill 即可取得多數效益，再考慮微調；DPO 需要 70B 以上模型與大量運算。Twin Review 尚未開源，Tapes.dev 為 Apache 2 開源。

### 重點
- 「pushback」標籤：工程師反駁 agent 的時刻，是專業知識（如 API 結構、避免重造已有的函式庫）的高訊號來源
- 順序建議：先用 trace 產生 skills → 建 evals → 再做 Qwen 4B 特化微調；DPO 需 70B+ 與較大算力
- 團隊約 80,000 筆 session 可作為 skill 來源；轉向 CLI 內審查導致 GitHub 上缺少審查評論
