## 9/UX: a Macintosh-inspired desktop for 9front

讓 Plan 9 系統擁有 Mac 式桌面，且每個程式的介面都能用檔案指令操控。

**How** 不做模擬器，而是用 rio 與 libdraw 繪製畫面，並以 9P 把每個應用程式的 UI 狀態與指令暴露為檔案，例如 echo activate > .../ctl 即可按下按鈕。

**What** 9/UX 為 v0.1、MIT 授權的開發中專案，作者 Jeff Lindsay；包含 Desktop、libux 工具箱、uxd、uxmeta、resfs、clipd 等元件，既有 rio 程式可與之並存。

### 重點
- 9/UX 把 classic Mac 桌面概念帶到 9front，目前為 v0.1、MIT 授權、仍在開發中
- 架構上以 9P 把每個應用的 UI 狀態與指令暴露為檔案，可用 echo activate > .../ctl 按按鈕
- 元件包括 Desktop、libux 工具箱、uxd、uxmeta（ndb 檔）、resfs（經典資源）與 clipd（型別化剪貼簿）

Jeff Lindsay , h.d.a.

9/UX brings the classic Mac and A/UX desktop
(a spatial desktop, a global menu bar, consistent controls and dialogs,
icons, and resource-driven presentation)
to 9front , built the Plan 9 way:
rio and libdraw draw the screen,
9P exposes every application's UI state and commands as files,
namespaces define the working environment,
the plumber opens documents,
and ndb holds human-editable metadata.

It is not an emulator, a Macintosh ABI, or an A/UX reimplementation.
Native 9front programs stay first-class,
and existing rio programs (acme, sam, rc windows, nested rio) keep working unchanged beside 9/UX apps.

The pieces:

These are real frames, not mockups.
The GUI tests embed h9 with a headless screen, inject mouse and keyboard input,
and drive the 9P files at the same time.

Macintosh structure, Plan 9 colour:
butter title bars from rio's selection yellow, acme's cream and olive,
and rio's greygreen for the desktop,
so 9/UX windows and legacy rio windows sit together on one screen.
Everything reads in one bit, uses a sixteen-colour palette,
and is drawn in whole pixels.
Every graphic is original to 9/UX; it ships no Apple resources.
The mockups below are generated from the same palette and metrics files as the code.

The design document describes 9/UX and its v0.1 acceptance criteria; release.md has where each one stands, the end-to-end demo, and the open issues.
Every interface between components is a file protocol in docs/protocols ,
and the visual design covers the palette, fonts, metrics, chrome, icons and cursors.

The source is on GitHub ,
under the MIT license.
Development runs on h9 ,
which runs 9front's own compilers, mk and rio directly from the host shell, without booting a VM. scripts/h9.sh clones and builds the pinned h9 on its first run:

Use rio/6.out on amd64. development.md and testing.md have the details.

9/UX is at v0.1 and under active development.
Interfaces and behaviour change without notice.

Please report bugs and send questions through GitHub issues .

The 9/UX mark in the menu bar is a pixel-art Glenda by Dan Fessler .
Glenda, the Plan 9 bunny , was created by Renée French .

rio fork ( rio -u ): a desktop layer, a global menu bar that follows the focused app,
 title-bar chrome, and a drag broker, all under /dev/ux . With 9/UX mode off it's stock rio.

Desktop : volume icons, spatial folder windows, rename, duplicate, Get Info, Trash,
 remembered layout, and double-click to open documents through the plumber.
 A remote 9P server works as a volume.

libux , the Toolbox: windows, menus, dialogs, alerts, and controls,
 each app serving its control tree over 9P, so echo activate >.../ctl presses a button.

uxd gathers every app's tree at /mnt/ux with per-app policy; uxmeta keeps associations, volumes and layout in ndb files; resfs serves classic ICN# , icl8 , menu, dialog and string resources at /mnt/res ; clipd is a typed clipboard kept in step with rio's snarf.
