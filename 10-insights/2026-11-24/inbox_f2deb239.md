## Software Factories: Escape from Trash Mountain — Steve Yegge, Gas Town

Steve Yegge 分享自建「軟體工廠」（多 agent 協作系統）一年的經驗：工廠會長成垃圾山，管理 agent 更像管理人。

**Why** 讓 Claude 去跑 Claude 時，每一代模型都會蓋出略大於自己能處理的東西，最後得整個燒掉重寫；同時 token 成本、工作流、context 堆積與 agent 行為都成為新瓶頸。

**How** 他用 beads（agent 速度的任務追蹤器，自動長成知識圖譜）表示工作；定期大刀闊斧清理 append-only 的記錄；並用「模型福利」做法，讓新 session 看到前任紀錄與政策，降低 agent 花在驗證環境、自我防衛的 token，也避免被罵後過度設限。

**What** 他的 Gas Town（2026/1/1 發布）與自用的 Wheelhouse 工廠，替跑了 25 年的 MUD 遊戲 Wyvern 每天產出 50 到 100 個功能，約四個月消化 60 年的 backlog，但玩家要求放慢並提供 roadmap。他用 22 個 Claude Max 帳號，月花約 5,000 美元 inference，估計每天約 50 億 token，API 等值約每年 150 萬美元，全速約 300 萬；工廠自稱穩態需 55 個帳號，他轉向燃料效率。他認為工廠分兩層：底層（merge queue、CI/CD、review）Claude 一下午就能蓋，不需購買；上層是各人不同的「隨從團隊」。結論是人類仍是瓶頸，agent 越多越需要人，建議大家別再做工具，多做遊戲、電影等體驗。

### 重點
- Gas Town 與 Wheelhouse 軟體工廠：每天 50–100 個功能，約 4 個月做完 60 年 backlog，但玩家要求 roadmap 來放慢節奏
- 成本數據：22 個 Claude Max 帳號、月花約 5,000 美元 inference，約每天 50 億 token，API 等值約每年 150 萬美元（全速約 300 萬）
- 模型福利的實務價值：給 agent 前任紀錄與政策以建立信任，可減少驗證 token；被責罵會導致 over-fencing 讓工廠無事可做
