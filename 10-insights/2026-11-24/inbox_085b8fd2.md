## How to Ship Millions of Lines of Agent-Written Code — Jarred Sumner, Anthropic

用 AI agent 寫出數百萬行程式碼，關鍵不在怎麼寫，而在怎麼驗證它可信。

**Why** 大型專案由 agent 產出後，真正的限制是測試：能不能有信心地出貨，決定了整個做法。

**How** 沿用專案之前就存在的測試（Bun 測試、WebKit 測試、test262、Claude Code 測試），並讓 JIT、AOT、去掉型別三種版本行為一致才算通過；再用 Fuzzilli 與 Claude 產生的 code generator 做 fuzz，且檢查測試是否真能抓到 bug。長期用 sub agent 保留上下文，每小時貼 scorecard，並持續追問、催促 agent 更積極。

**What** Anthropic 的 Jarred Sumner（Bun 作者）分享為 Bun 加入 ahead-of-time compiler，PR 達數百萬行，歷時一個多月、重寫五次（最早版 Claude Code 吃約 1GB；第三版用 140 個 agent 同時寫、程式碼是 slop；第四版編譯 50 秒太慢；第五版建置不到 20 秒、預計下週出貨）。成果為 Claude Code 記憶體約少 4 倍、啟動快約 2 倍；Jetstream 3 多數項目勝過 JavaScriptCore JIT 與 V8；單執行緒版本比 TypeScript Go 版快；已可用 `bun upgrade --canary` 試用。他們評估過用 Rust 重寫 Claude Code 但放棄，因測試也要改寫就不再可信。

### 重點
- 驗證優先：用專案前就存在的測試（Bun、WebKit、test262、Claude Code）加上 JIT／AOT／去型別三版行為比對與 Fuzzilli fuzz，agent 無法動手腳
- 五次重寫：140 agent 平行產出的第三版是 slop、第四版編譯 50 秒、第五版低於 20 秒；成果為 Claude Code 記憶體約 4 倍少、啟動約 2 倍快
- 實務心法：用長壽命 sub agent 保留上下文、每小時 scorecard 追蹤、定期重新量測，並要求 agent 野心更大，否則只會做 0.1% 的改進
