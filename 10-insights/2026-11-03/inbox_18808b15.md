## Your AI Agents Shouldn't Care Where They Run - Nikhil Harithas, Factory

把 agent 的運算資源（在哪跑）從 agent 本身抽離，讓企業用自己的 VPC 與運算環境跑 agent。

**Why** Blackstone 等大型金融客戶有嚴格的安全與法規限制，不能讓 agent 跑在筆電或廠商環境，且只接受對外連線、不接受入站連線；單純在客戶機器上裝 agent 又得讓客戶自己處理運算生命週期。

**How** Factory 設計 open compute：compute gateway 透過 driver（EC2、Kubernetes、Daytona、Modal 等各一個）在客戶 VPC 建立機器，機器主動以 websocket 對外連到 Factory 的 relay，client 的請求經 relay 轉送，LLM 呼叫可用客戶自己的 key（如 Bedrock）。

**What** 講者（Factory 的 forward deployed engineering 負責人）介紹其 coding agent Droid 與此預計數週後開源的專案；抽象管理的對象是「電腦」而非 session，支援暫停、恢復、快照、fork，並能處理 AWS microVM 8 小時上限（以快照換機延續多日任務 missions）；driver 只要符合規格即可讓 Droid 直接生成。

### 重點
- 架構：client → 後端 compute gateway → open compute 控制器 → driver（EC2／K8s／Daytona／Modal）→ 客戶 VPC 內機器主動以 websocket 連回 relay，客戶端永遠只需對外連線
- 抽象單位是電腦而非 session，支援 pause／resume／destroy／snapshot／fork，快照可存客戶自己的 S3，並從客戶 secret store 注入機密
- 遇到 microVM 8 小時上限時，以快照搬到新沙盒延續跨日多 agent 任務；driver 以規格驅動，可交給 Droid 依規格自動生成
