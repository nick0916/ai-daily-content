## When Running Your Own AI Models Beats Paying for APIs - Steven Latré, imec

比較用 API 與自己架設開源模型跑 coding agent，何時自架才划算。

**Why** token 用量成長後，單靠 API 與模型路由不夠，企業開始考慮自管 AI stack，但自架會讓硬體、模型、harness 的設計空間暴增。

**How** imec 以 SWE-Bench Pro 長時程任務，搭配 Codex、Pi、Claude Code 三種 harness 與多種開源模型和硬體配置，跑了數千次，量測解題率、延遲與成本，並做總持有成本（TCO）分析。

**What** 開源模型可分三級：Qwen 與 DeepSeek 約 30–40% 解題率，GLM 約達 Opus 等級，Kimi K3 達 86%。Qwen 與 DeepSeek 表現相近但租 GPU 成本差 4 倍；GLM 換 Kimi K3 準確度約 +20%、GPU 成本僅 +15%。Kimi K3 僅能穩定支援約 4 位並行使用者且延遲慢 3 倍；低階硬體需 89% GPU 使用率才划算，高階（如 B200 級）只要 15%；GLM 級應用自架可省約 25% TCO。harness 準確度相近，但 Codex 搭 GLM 產生的 token 只有一半，GPU 時間與帳單也減半。imec 計畫公開完整 benchmark 資料集並成立軟硬體聯盟。

### 重點
- 自架 TCO 門檻：低階硬體需 GPU 使用率約 89% 才勝過 API，高階硬體（如 B200）僅需約 15%；GLM 級 coding 應用約省 25% 成本
- 並行度比準確度更限制自架：Kimi K3（SWE-Bench Pro 解題率 86%）只能舒適支援約 4 位並行使用者，延遲仍比 Claude Code 基準慢約 3 倍
- harness 選擇不影響解題率卻影響成本：Codex 搭 GLM 產生的 token 與 GPU wall time 約為其他 harness 的一半
