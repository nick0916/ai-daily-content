## Your AI Agent Wants Your Data. Here's How to Lock It Down - Jeff Smith, Oracle

不讓 AI 自己亂寫 SQL，而是只讓它挑選事先寫好的報表，並把權限控管放在資料庫端。

**Why** 自然語言轉 SQL 常產生看似正確、實際問錯問題的結果，還會暴力掃描資料庫而耗費大量 token。

**How** 把團隊既有報表包成參數化的 list reports / execute reports 兩個 MCP 工具（報表可達 500 份卻不佔 500 個工具名額）；另提供 schema info 工具回傳壓縮的 JSON 結構；身分則經公司 SSO 的 scope 與角色傳到資料庫，由資料庫動態過濾回傳結果（Deep Data Security）。

**What** Oracle 的 Jeff Smith 在 AI Engineer 講 Oracle AI Database 的 MCP server：可關閉任意 SQL、只允許自訂工具與報表，並支援 generate annotations、讀取用的 Data Guard standby 供 agent 排查效能問題；MCP apps 預計今年稍後推出。

### 重點
- 把既有報表轉成參數化工具（list reports / execute reports），LLM 最多選錯報表，不會生成錯誤 SQL；500 份報表只佔 2 個工具
- 權限控管放在資料庫層而非工具層：經 SSO 取得 scope 與角色，資料庫動態剔除結果集中不該看的資料（Deep Data Security）
- schema info 工具以 verbose/medium/slim 模式回傳壓縮 JSON，取代 agent 反覆查表、欄位與抽樣資料；效能調校則讓 agent 只在 Data Guard 唯讀 standby 上操作
