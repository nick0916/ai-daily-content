## The Sweet Side of the Bitter Lesson — Thariq Shihipar, Independent

離開 Anthropic 的 Thariq 回顧自己對 AI 的幾個預測錯在哪，並主張模型是能適應人的工具，不是迫使人屈就的外星智慧。

**Why** 軟體工程師是 AI 採用的前緣，軟體發生的事之後會發生在其他知識工作，所以如何看待模型能力很重要；他也發現 vibe coding 時自己常搞不清楚角色到底做了什麼，難以產出值得稱為「文藝復興」的高品質軟體。

**How** 他把程式碼庫分成兩部分：agent 寫的引擎程式碼，以及一個他自己讀、有 lint 規則、讀起來像英文的「human」spec 資料夾，等於為遊戲打造一種自訂腳本語言（用公尺等單位、有註解），複雜原語仍請 Claude 實作。

**What** 他承認自己錯估了「Bash is all you need」（現在反而偏好 MCP 勝過 CLI，另有 code mode、skills、progressive disclosure）、「React is all you need」與「diffusion 會吃掉藝術」。他提出「jagged frontier 之下是 smooth interior」：模型能力越強，寫 React、HTML、Swift、Figma JSON 的表現都差不多；並以 Karpathy 的陸地/水面座標評測為例，稱 Opus 4.6 地圖模糊、Opus 5.5 近乎完美。他的 2D 等角格鬥遊戲搭配 Cursor tab 模型，被他形容為以腳本語言為 spec 的 spec-driven development。

### 重點
- 預測失準清單：Bash is all you need、React is all you need、diffusion 吞噬藝術，皆未成真；作者現偏好 MCP 勝過 CLI
- 「smooth interior」：能力邊界以內，模型對 React/HTML/Swift/Figma JSON 等不同輸出格式表現相近，不必被單一語言綁定
- 實務做法：把 codebase 分成 agent 引擎碼與人類可讀、有 lint 的 human spec 資料夾（類自訂腳本語言），讓人保有對行為的掌控
