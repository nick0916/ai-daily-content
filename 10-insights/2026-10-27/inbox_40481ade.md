## Stop Giving Your Agent Tools. Give It a Sandbox - Mikyo King, Arize AI

別給 agent 一大堆工具，改給它一個能寫程式的沙箱，讓它自己組合工具。

**Why** 傳統 tool calling 會把整個工具目錄與每次輸出塞進 context，造成 context rot、多輪往返、成本與延遲上升。

**How** Code mode 讓 agent 先搜尋所需工具、再在程式環境中以序列、平行、條件式方式呼叫，只把必要結果回傳 context。

**What** Arize Phoenix 的 agent 加入 bash、Python sandbox、REST CRUD 端點、SQL 與綁定 UI 的 web worker；用 Harbor 框架（關網路、多次 trial、pass@k）評測，導入 code mode 後 token 減少 43%、成本降低 31%、延遲大致持平。講者也列出風險：資源、網路 egress、secrets、權限過寬、除錯變難、無法從中斷處續跑。

### 重點
- Arize 實測 code mode：token 減少 43%、成本降低 31%，沙箱有額外開銷但延遲大致不變（跨 Claude Code、MCP、CLI 多個介面驗證）
- Code mode 四個好處：工具漸進式揭露、可組合（平行 fan-out/串接）、token 效率、能自建工具（如先移除 PII 再處理資料，避免敏感資料進 context）
- 代價與未解問題：沙箱資源與網路 egress、secrets 不得回流 context、權限組合過寬、MCP 與 harness 雙重沙箱的序列化負擔、執行中斷無法續跑、小模型在 code mode 表現較弱
