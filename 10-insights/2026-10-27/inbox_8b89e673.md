## We Kept Rebuilding Our AI Agent. Here's What Survived - Fuad Ali, Arize AI

把 AI 代理拆掉重建兩年後，留下來的只有簡單的 harness 設計：計畫與結束由程式碼管、記憶用一個小檔案。

**Why** 模型自己管 to-do、處理超大工具結果、跨 session 記憶時容易失焦、爆 context 或過度工程化。

**How** 把計畫以訊息形式由 harness 每輪注入、用明確 finish 呼叫並在計畫未完成時最多退回三次、大型 JSON 截斷後讓 agent 用 jq 自己找、歷史由模型寫 checkpoint 再丟棄舊內容、長期記憶改由背景工作維護每位使用者一個 markdown 檔。

**What** Arize 的 in-product agent Alex（2023 年底原型，2026 年 2 月 Alex 2.0，6 月 One Alex 合併為單一 agent 按需載入 skills）。不使用 agent framework；長期記憶試過向量檢索、知識圖譜，最後以上限 8,000 字元的 markdown 檔勝出；預設模型選「夠快夠好」而非最新，並以 production traces 當回歸測試集、用 Signal agent 讀 Alex 的 traces。

### 重點
- 計畫管理演進：純 to-do 工具會讓模型把時間花在勾選清單上（20+ 次迭代）→ 由 harness 把計畫當訊息每輪注入 → 移除 in-progress 標記 → 目前測試完全不用工具；結束 turn 改為明確 finish 呼叫，計畫未完成最多退回 3 次，並在迭代上限前一步警告、之後強制結束
- 長期記憶：試過向量檢索、episodic/semantic store、temporal knowledge graph，最後採每位使用者一個 markdown 檔（上限 8,000 字元），session 結束後由背景工作寫入，小、精確、易於人工稽核
- 專家 sub-agent 從 10 個（每頁一個）收斂成單一 agent 按需載入 skills 與工具；簡單任務（如 AI filter 產生）甚至只需單次模型呼叫，不需要 loop
