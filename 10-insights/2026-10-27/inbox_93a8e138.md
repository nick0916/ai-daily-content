## 300 Agents, 60 People: How We Secured Our Own AI Agents - Aiden Sochowski, Runlayer

公司內部 50–60 人卻跑著 300 多個 agent，要靠集中記錄每次 session 與 tool call，才看得見風險與浪費。

**Why** 員工在本機或第三方產品自行跑 MCP client、到處授權，企業幾乎沒有可見度；agent 又能快速混合不同資料等級，擴大攻擊面。

**How** 部署 gateway 記錄所有 session 與 tool call，依主題與風險分類；自訓分類器檢查每個 tool call 是否偏離 agent 原本定義的目的；用歷史呼叫建議可移除的權限。

**What** Runlayer 分享自家經驗：300+ agent 每天運行；發現的問題包括 email prompt injection 外洩、PR 審查 agent 在長 session 中被說服而核准、招募 bot 權限過多、非工程人員 vibe code 的 MCP server 反覆報錯導致成本暴增，以及改用更貴模型使成本一週內增加到約 100 倍。

### 重點
- 威脅常橫跨整段 session 而非單一 tool call（如 PR 審查 agent 被作者反覆說服而核准），因此需要用分類器對照「agent 原定目的」逐一檢查每個 tool call，而不是只靠靜態規則
- 單一 agent 讀到被污染的資料（如惡意履歷）會影響其他共用系統的 agent；對策是嚴格限縮 agent 可寫入的系統範圍，以保持 context 不被污染
- 監控也能省錢：外行 vibe code 的 MCP server 因格式錯誤反覆失敗，讓 token 成本膨脹；切換到更貴模型一週內成本膨脹約 100 倍——需要預算、rate limit 與錯誤監控
