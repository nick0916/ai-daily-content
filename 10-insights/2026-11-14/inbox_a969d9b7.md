## All Code Is Slop (Except Mine) — Lauren Tan, SpaceXSI

先把程式碼庫的限制與驗證機制做好，AI agent 才能大量產出 PR 而不拉低品質。

**Why** agent 會複製程式碼庫裡既有的 workaround 與壞模式，雜草一長就擴散；PR 量從每天幾個變成幾百個後，人工 code review 撐不住。

**How** 用「倒金字塔」分層：最底層用 lint 規則、型別、API 與架構設計等確定性手段約束 agent，中間疊執行期驗證與形式驗證，最上層才用 rules、skills、agents.md 這類需要判斷的文字指引；每次糾正 agent，都優先轉成 lint 檢查，而不是多寫一行規則。

**What** 講者 Lauren Tan（SpaceXSI，負責 Graphbot）在 AI Engineer 演講中表示，上個月她個人上線 3,000 個 PR，團隊上線 11,000 個 PR，約每天發一個 stable 版本；10 月有 227 人至少貢獻 1 個 PR，revert 比例穩定在約 0.5%，且啟動、開新對話、切換對話等效能指標比發布時更快。實作包括：自家 client 框架 Dune 禁用 useEffect、以 electron main／renderer 目錄結構搭配依賴分析禁止跨層 import、禁用 99% 的程式碼註解，以及用 TLA+、Lean、Bombadil（UI property-based testing）做驗證。

### 重點
- 倒金字塔優先順序：確定性層（API／架構／lint／型別／測試）→ 驗證層（執行期與形式驗證）→ 文字指引層（rules、skills、agents.md）；糾正 agent 時優先改程式碼庫，使其成為可重現的檢查
- 具體 guardrail：Dune 在產品程式碼禁用 useEffect；electron main 與 renderer 目錄互相 import 被依賴圖分析與 lint 禁止；禁用 99% 註解，因為 agent 會用註解替壞掉的快速修法辯護，且註解無法強制執行
- 結果數據：團隊上月 11,000 個 PR、約每日一個 stable 版本、227 位貢獻者、revert 率約 0.5%；引述 Cindy 的說法，其每日 token 約 70% 花在驗證，講者也表示自己的用量大多在驗證
