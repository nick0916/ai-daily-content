## v3.59.8 — tombstone payload scrubbing + config_list default-scope fix

修正 memory 刪除後資料仍殘留於磁碟的問題，並修正 config_list 漏列非預設 scope 的值。 **Why** soft delete 只把 status 改為 deleted，content、embedding、tags、metadata 仍留在檔案中，可從原始檔案還原。 **How** tombstone 更新時清空這些欄位，並在 sql.js 與原生刪除路徑啟用 PRAGMA secure_delete = ON，使釋放的 SQLite 頁面不保留舊資料。 **What** config_list 的 scope 合併迴圈把 default 當成精確比對，導致只存在於非預設 scope 的值在預設視圖中被靜默丟棄（#4351、#4354）。

### 重點
- soft delete 後 content、embedding、tags、metadata 原本仍留在磁碟，現於 tombstone 更新時全部清空
- 同時啟用 PRAGMA secure_delete = ON，避免 SQLite 釋放的頁面殘留舊位元組
- config_list 的 default scope 分支不可達，修正後非預設 scope 的值會正確合併進預設視圖

Fixes 
 
 memory_delete / purgeNamespace now scrub the tombstone row's payload ( #4351 ). Soft-deleted 
entries previously left content , embedding , tags , and metadata intact on disk with only 
 status flipped to 'deleted' — recoverable from the raw file image. The tombstone UPDATE now 
clears all of those fields, and both the sql.js and native delete paths enable 
 PRAGMA secure_delete = ON before deleting so freed SQLite pages don't retain the old bytes 
either. 
 config_list now correctly merges non-default scopes into the default view ( #4354 ). The 
scope-merge loop treated scope === 'default' identically to an exact scope-name match, which 
made the else if (!merged.has(key)) branch — already documented as the intended "merge other 
scopes in without overwriting" behavior — unreachable for the default case. A value set only at 
a non-default scope was silently dropped from the default-scope listing.
