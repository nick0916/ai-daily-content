## v3.59.3 — Windows memory-list crash fix

避免 CLI 在結束時因 libuv 斷言而崩潰，特別是 Windows 上的 memory list。

**Why** memory list 等指令偶爾在退出時出現 UV_HANDLE_CLOSING 斷言錯誤，Windows 上較明顯。

**How** 退出處理改為設定 process.exitCode，不再強制 process.exit(0)，並盡力 await shutdownBridge() 清空快取的 memory-controller 資源，讓事件迴圈自然結束。

**What** Ruflo v3.59.3（#4334），三個 dist-tags 已在 registry 驗證。

### 重點
- 退出處理改用 process.exitCode，不再強制 process.exit(0)
- 盡力 await shutdownBridge()，釋放快取的 memory-controller 資源後讓事件迴圈自然關閉
- 修正 UV_HANDLE_CLOSING 斷言，Windows 上較常見（#4334）

Fixes 
 
 memory list (and other CLI commands) could intermittently crash on exit with a libuv 
assertion ( UV_HANDLE_CLOSING ), most visible on Windows ( #4334 ). The CLI's exit handler now 
sets process.exitCode instead of forcing process.exit(0) , and best-effort awaits 
 shutdownBridge() to drain cached memory-controller resources before the event loop closes 
naturally. 
 
 Published 
 
 @claude-flow/cli@3.59.3 , claude-flow@3.59.3 , ruflo@3.59.3 — latest / alpha / v3alpha 
dist-tags all verified matching on the live registry.
