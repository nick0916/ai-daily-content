## Build the Workshop Before the Software Factory — Armin Ronacher, Earendil

模型變強後，瓶頸不在工具而在人的注意力，所以要先把個人工作流打磨好，再談自動化軟體工廠。

**Why** Agent 跑得越久、產出越多，但人類的注意力、理解力與協作能力沒有成長；專案容易無節制膨脹，也會衝擊沒準備好的外部系統。

**How** 作者用自己的 Pi 工作階段資料佐證：核心 harness 一年沒改，修正次數卻隨模型進步下降；對策包括在約 70% 進度時讓 agent 產出簡短摘要與 HTML 頁面方便驗證、堅持少依賴與標準格式、打造可暫停／恢復的 durable agent，以及用 code mode 搭配 classifier 模型編排大量工作。

**What** Armin Ronacher（Earendil，Pi coding agent）的演講。數據：P90 的 agent 執行時間從去年 12 月 Opus 4.6 的約 2.5 分鐘升至最新模型的 14 分鐘以上；每日 prompt 數約 120–190 持平，agent 活躍時間卻成長到數倍於工作日；累計建立 141 個專案，但持續提交的僅約 10–15 個。

### 重點
- Pi 核心 harness 與工具自去年 12 月未變，但隨模型進步，使用者修正與中止次數持續下降；P90 agent 執行時間由約 2.5 分鐘（Opus 4.6）升至 14 分鐘以上
- 人的注意力是瓶頸：每日 prompt 約 120–190 持平、agent 活躍時間暴增，141 個專案中只有約 10–15 個持續維護；對策是在約 70% 進度請 agent 產出摘要與 HTML 頁面，並堅持少依賴、維護標準格式
- Harness 方向：durable agent 可暫停／恢復並搭配 flex scheduling 省成本；code mode（以 JavaScript 編排工具呼叫）搭配便宜快速的 classifier 模型，可處理如 3,000 件客服請求
