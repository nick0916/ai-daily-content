## How Anthropic builds software in 2026 with Katelyn Lesse

Anthropic 平台工程負責人說明，他們如何用 Claude 把服務所有 Claude token 的 API 從 Python 重寫成 Rust，並重塑日常開發流程。

**Why** 原本的 Python monolith 是 2023 年研究團隊為了方便整合推論基礎設施而寫的，後來 CPU 用量成為日益嚴重的問題，加上全球 CPU 短缺。

**How** 讓新的 Rust API 對正式流量做 shadowing，持續迭代到回應與舊 Python API 完全一致；現有 API 就是完美的測試基準，所以只需仔細看約 20% 的程式碼。

**What** Katelyn Lesse 稱重寫由幾位工程師花約五個月完成，且無人是 Rust 專家。Anthropic 另有全程運作的 Claude code review 分類器，決定是否需人工 review、需幾位、送哪個團隊；API oncall 由 Claude agent 先接警報；新人 onboarding 是「問 Claude」；團隊仍是 5–8 人的 two-pizza team；因強候選人常在寫程式面試失利，已逐步淘汰傳統寫 code 面試；晉升改看專案影響（CPU 節省、延遲、避免的事故）而非完成時間。

### 重點
- Python→Rust 重寫：幾位工程師約五個月、無 Rust 專家；Rust API 對正式流量 shadow Python API 直到回應一致，約只細看 20% 的程式碼
- Code review 分類器：機械化低風險變更（SDK 版本升級、換新模型、修 flaky test）可不經人工 review，其他則由 Claude 評分風險、決定人工 review 數並路由到團隊
- 不變的部分：規劃對齊時間與 pre-AI 差不多、仍是 5–8 人 two-pizza 團隊；變化的部分：工程師花更多時間做工具、晉升不看專案完成時間而看影響

Today’s guest is Katelyn Lesse, who leads platform engineering at Anthropic and previously led engineering teams at Stripe. Her team owns the Claude API and the infrastructure behind products like Claude Code and Claude Desktop. We start with Anthropic’s move from a Python monolith to Rust. Katelyn explains why adding CPU capacity is tricky due to a global CPU shortage, how Claude helped engineers get up to speed in Rust, and how the team used shadowing to verify the rewrite against production traffic. Just today, Katelyn and the team published a deepdive on their Python → Rust migration. Katelyn walks us through what the software engineering job looks like today at Anthropic, and how code review and oncall interact with agentic workflows. We also get into the frontier lab’s “software factory”, how a product manager shipped a feature to production, and why Anthropic is replacing traditional coding interviews with agent-based exercises. As of last week, Anthropic is a publicly traded company, with a market capitalization of around $1T, all while having a tenth of the headcount of other businesses with similar market capitalizations. Learning how Anthropic does software engineering might be instructive for companies that want a similar structure. Takeaways from the conversation with Katelyn Here are 12 interesting learnings on how software engineering is changing inside of Anthropic: 1. Anthropic rewrote its API from Python to Rust in around five months. The API called ‘Messages API’ serves all Claude tokens externally, as well as for Claude Code and Claude Desktop. This service does authentication, tokenization, billing, and safety checks, then calls the GPU stack to generate tokens. The service was a Python monolith and the team initially optimized Python, but found the performance overhead was still large. Eventually, they decided to rebuild it in Rust. It took a few engineers and a few months in total; all without anyone being expert in Rust! How the Claude API team had the Rust system shadow the Python one. See more details in the Anthropic engineering blog about the migration The Anthropic team published a longer walkthrough of the migration – check it out. 2. Hang on, why was the monolith written in Python in the first place? Back in 2023, Anthropic was still a research company when it decided to create an API, and the team that built it was small, with a large crossover to Research. It was the case that researchers worked mostly with Python, which made it very easy to integrate the API with inference and other infrastructure code. Similarly, OpenAI’s API was also written in Python – and later rewritten to Rust . Anthropic and OpenAI faced the same challenge with the Python monolith: the CPU footprint of the monolith started to become a growing problem. 3. The rewrite was done without Rust experts on the team or strict code reviews. A year earlier, the same team picked Go for their new services because it was a language that team members knew how to read and write. But by 2026, they felt that Claude was good enough at Rust, and Claude helped engineers learn more about Rust during the rewrite. The team did not do strict code reviews, but had the “unfair” advantage of the existing Python API being a perfect test harness. They set up the new Rust API to shadow the current API, and iterated until all responses were identical. Also, Katelyn estimates that engineers looked closely at only ~20% of the code generated: “As long as you can really boil something down to make it verifiable in some way, then you don’t have to look at every single line of Rust code that’s getting written.” 4. Anthropic has its own code review agent running at all times. The company has a Claude code review classifier running for all pull requests. It decides: Does it need a human review? For “mechanical” and low risk changes like an SDK version bump or using a newer model, Claude can decide there’s no human review needed. This is also the case for fixing flaky tests, in which case, another Claude does the review, then merges and deploys it. How many human reviews does it need? For changes that do need human reviews, Claude scores the risk and takes into account additional rules to decide how many human reviews are needed. Which team needs to do a review? Claude routes the PR to the right teams. 5. A Claude agent is paged before a human for API oncall. For months, a Claude agent has been shadowing the API oncall rotation of the API team for training. As the team have gained confidence that Claude can tell if an alert is “real” or “noise,” they now let this agent categorize an incoming alert first. The long-term goal is for Claude to handle actual incidents without waking up a human – but they’re not there yet. We cover more on how AI SRE startups are tackling the same challenge in our recent deepdive, AI SRE: what is it, how could it change on-call – and does it work? 6. Onboarding for new Anthropic engineers is “talk to Claude.” New joiners at tech companies used to have “onboarding buddies” and engineers who explained the architecture of systems to them, often by drawing boxes and diagrams. Not so at Anthropic, where Claude is connected to the codebase and internal systems, and engineers just ask it to explain how things work. Claude can even create interactive tutorials and visualizations. It’s pretty similar to how OpenAI engineers use Codex for onboarding, as covered in our podcast episode with Tibo Sottiaux . 7. One thing that hasn’t changed is the need for planning and alignment. Katelyn’s team interacts with Inference, Research, Safety, and App teams. When kicking off a project, a lot of time and effort is spent on getting everyone on the same page. Katelyn says that planning time has not changed much from “pre-AI”. The average engineer actually spends more time coordinating than on implementation! 8. Another thing that has not changed is two-pizza teams . Teams at Anthropic are still two-pizza teams of around 5-8 people. Katelyn says it’s because this is the right size for understanding a complex system and staffing an oncall rotation. Teams still own systems, and get paged. And it is a team – not an individual – that’s responsible for each system! 9. Engineers at Anthropic spend a lot more time building tooling than before. Even on product teams, engineers are spending a lot more time building tools that help them to accelerate their own work. For example, an engineer on Katelyn’s team set up a Slack channel that runs a multi-agent team towards a single goal, even though it was not a task assigned to the engineer. 10. Knowing a programming language well is starting to not matter. Katelyn invested a lot of time, pre-AI, into learning languages. I asked if it hurts as an engineer to consider that programming languages matter less these days, with AI. Katelyn pointed out that some engineers always cared little about languages, and for engineers who love languages, she says there’s still work to be done on languages and frameworks themselves. 11. Katelyn’s team phased out the coding interview after strong candidates kept failing it. Candidates who crushed other interviews were starting to fail the coding one because they no longer write code by hand. In the absence of a set replacement, the team is actively experimenting with interviews conducted together with coding agents. The design (architecture) and project deepdive interviews remain unchanged. 12. For promotions, the “time to complete a project” is now meaningless. Anthropic still has levels and a promotion process. But the time taken to completion is pretty meaningless when a year-long project can now be done in days or weeks with AI! Katelyn says that they fall back on evaluating the impact of projects; for example, how much CPU usage was saved, how much was latency reduced by, or how many incidents were avoided. Katelyn’s message to engineers with an identity crisis: humans have plenty of engineering to solve, related to agents. She has written about this in detail . The takeaway: “This is for the engineers feeling an identity crisis because they think their knowledge and skills won’t be important: you and your skills can be the difference in whether or not agentic infrastructure-related problems get tackled, and whether multiagent systems can solve the world’s hardest problems. You can and should go deep in these domains, learn new things, and form opinions. So much of this problem space is wide open for new solutions.
