## An AI Agent Got Its User Banned From Resy — Keycard, JPMorgan Chase & AAuth

Keycard、JPMorgan Chase 與 OAuth 共同創作者 Dick Hardt 的座談，主題是 agent 的 intent-based（意圖式）runtime authorization，即針對每次 tool call 授權，而非讓 agent 持有廣泛的長期權限。與談人指出現有系統多為粗粒度：Salesforce 長期只有單一 scope「API」；Notion MCP server 可以取得頁面，卻無法只取該頁上的某個資料庫。Dick Hardt 表示 OAuth 原本為網站對網站設計，需預先註冊、依賴瀏覽器 redirect，並不適合事先不知道要做什麼、每個 instance 需求不同的 agent，把既有 scope 直接對應到 agent 太粗。JPMorgan 的 Michael Davis 觀察到較成功的企業會像對待新進開發者一樣「onboard」agent，隨成熟度逐步放權，並用環境脈絡（例如 sandbox 是否在隔離環境）調整自主程度；他也以銀行從授權人轉向授權交易、支票 memo 欄位記錄意圖為例。Hardt 提到在 AAuth 工作中提出「mission」概念：授權決策要放在整體任務脈絡內，例如避免 5 秒前才付過的款項再次重複支付。（標題提到 Resy 封鎖用戶的事件，但所提供的內文片段未涵蓋該案例。）

### 重點
- 粗粒度問題：Salesforce 曾只有單一 scope「API」；Notion MCP 可取頁面但無法只授權某資料庫
- OAuth 為預註冊、瀏覽器 redirect 情境設計，不適合事先不知需求的 agent；AAuth 提出以「mission」承載整體意圖
- 企業做法：像 onboard 開發者一樣漸進放權，並以環境脈絡（如是否在 sandbox）決定自主程度
