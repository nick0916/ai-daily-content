## Why Humans Can't Keep Up With AI-Written Code - Tariq Shaukat, Sonar

AI 寫程式太快，人看不完，所以要靠明確意圖、導軌、獨立驗證與證據來建立信心。

**Why** 講者稱程式碼已變得豐富、信心才稀缺：非同步 agent 讓程式行數增加 2450%、commit 增加 240%，但 release 只增加 30%，人在迴圈（human in the loop）無法規模化。

**How** 提出「code confidence formula」，把意圖（intent）、導軌（guide rails，輕推 agent 留在路上，而非只擋住它）、獨立驗證、證據四項相乘，任一項為零則信心歸零。

**What** Sonar CEO 在 AI Engineer 的演講。引用研究：人在 AI 正確時 93% 同意，AI 錯誤時仍有約五分之四同意（cognitive surrender）；每步 95% 準確率跑 20 步剩約 36%；LLM 當裁判有 7–17% 結論不一致。Sonar 自家數據：Sonar Vortex 降低 36% token 成本、commit 內問題減少 92%；SonarQube 用戶認為 AI 寫碼對安全有非常正面影響的機率高 81%（此為廠商自家客戶調查）。

### 重點
- 非同步 agent 使行數 +2450%、commit +240%，但 release 僅 +30%：產出變多不等於能出貨，瓶頸移到驗證
- Code confidence formula = 意圖 × 導軌 × 驗證 × 證據，任一項為零整體信心即為零；講者主張用 guide rails（導軌）而非 guardrails（護欄）
- Sonar 自家數據：Vortex 在大型程式庫長任務降低 36% token 成本、commit 問題減 92%；調查中 SonarQube 用戶對安全、上市時間、停機頻率的正面感受分別高 81%、34%、76%
