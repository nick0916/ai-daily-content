## llm 0.37.3

修補 LLM 命令列工具在新版 SQLite 下記錄日誌壞掉的 bug。

**Why** Homebrew 改為提供 SQLite 3.54.1，其對 JSON 子查詢行為的修正讓 LLM 的日誌寫入程式碼失效。

**How** SQLite 3.54.1 起，`(SELECT json_array(...))` 依文件回傳 SQL 文字而非 JSON（D. Richard Hipp 表示 3.54.0 才是 bug），因此改用 `json((select json_array(1)))` 包一層來還原預期行為。

**What** LLM 0.37.3 為 bug fix 版本，主要處理最新 Homebrew 套件的相容問題；範例中 `select json_object('a', (select json_array(1)))` 在 3.54.0 回傳 `{"a":[1]}`，在 3.54.1 回傳 `{"a":"[1]"}`。

### 重點
- SQLite 3.54.1 修正 bug：`(SELECT json_array(...))` 依文件回傳 SQL 文字而非 JSON，導致 LLM 日誌程式碼出錯
- Workaround：以 `json((select json_array(1)))` 包住子查詢，輸出回到 `{"a":[1]}`
- LLM 0.37.3 是針對最新 Homebrew 套件（內含 SQLite 3.54.1）的修補版

Release: llm 0.37.3 
 A bug fix release for LLM , mainly to cover a problem with the most recent Homebrew package of the software. 
 Homebrew now ships the latest SQLite, 3.54.1 , which includes a fix that broke LLM's logging code . 
 Short version: in SQLite 3.54.0 the following SQL: 
 select json_object('a', (select json_array(1)))
 
 Returns this: 
 {"a":[1]}
 
 But in 3.54.1 the same query returns this: 
 {"a":"[1]"}
 
 According to D. Richard Hipp : 
 
 That was a bug fix. Per the documentation, (SELECT json_array(...)) returns SQL text, not JSON. Hence the 3.54.1 behavior is correct and 3.54.0 was a bug. 
 
 The workaround looks like this: 
 select json_object('a', json((select json_array(1))))
