## Your AI Agent Starts Every Session Like a New Hire - Killian Carlsen-Phelan, Sonar

在 AI 寫程式的迴圈裡先給它專案規範、寫完立刻用確定性規則檢查，不要等到 PR 才發現問題。

**Why** 每次新 agent session 都像新員工，不知道專案慣例與架構規則，得花 token 到處搜尋；且 agent 會複製既有問題並引入新漏洞，PR 階段才抓已經落後。

**How** 外掛先提供該專案的編碼指引與程式碼關聯地圖，agent 每次編輯都觸發快速檢查，結束回合前再跑跨檔資料流的深度分析，有問題就退回 agent 修到通過；強調用確定性分析而非 AI 檢查 AI。

**What** Sonar Vortex 是接到 Claude Code、Codex 等 agent 的外掛（基於 CLI 與 MCP，建立在 SonarQube 之上）。Sonar 稱平均少用 36% token、正式環境事故減少 44%；其調查指 96% 開發者不完全信任 AI 程式碼，但只有 48% 會在提交前完整驗證。以上數字為廠商自述。示範中 agent 建立的暫存檔未明確設定權限，被抓到並迫使其重修。

### 重點
- Sonar 調查：96% 開發者不完全信任 AI 產生的程式碼，僅 48% 會完整驗證後才推送
- 廠商宣稱：平均少用 36% token（尤其重構任務）、正式環境事故減少 44%（自述數據）
- 分三階段：先導引（指引+程式碼地圖）→ 編輯即檢查 → 結束前深度跨檔資料流分析；主張確定性驗證優於 AI 自我審查
