## Catch the Bugs Your Code Review Misses - Killian Carlsen-Phelan & Taylor Luttrell-Williams, Sonar

讓另一個 AI 在 PR 階段檢查 AI 寫的程式碼，連業務規則與 CI 失敗都一起查、一起修。

**Why** AI coding agent 寫碼又快又多，人工 review 變成瓶頸，而且 agent 不知道團隊的架構與規範，導致 production incident 增加。

**How** 在 PR 開啟時觸發 review，綜合 PR diff、CI logs、專案說明檔與規則（.review 目錄的 MD 檔、rules）產生 findings 與修正；用留言指令控制自動套用與自動合併，並反覆迭代到 CI 全綠。

**What** Sonar 的 code change verification agent（逐字稿拼寫為「Guitar」，應為語音辨識的拼寫，本文沿用）。三個 workshop 情境：(1) 預設 review 抓到「票轉讓後原購買者仍可退票」，bug 在 diff 之外的 orders.py；(2) 用 rules 檢查新增 $3.50 服務費違反「顯示價格須為全含價」的業務規則；(3) 診斷 CI 失敗（票可被重複掃描），用「auto apply on」「automerge on」留言自動修復並合併。進階功能含 Jira/Linear/Slack 整合、依 reviewer 資歷加權的 knowledge、cross-repo 與 cross-PR 分析；有 14 天 Pro 試用，講者定位為與 SonarQube 靜態分析互補。

### 重點
- 預設 review 找到 diff 外的邏輯 bug：轉讓票後原購買者仍可取消並退款，問題在既有的 orders.py，測試只涵蓋「已作廢票不可轉讓」而漏了反向
- 兩種注入脈絡的方式：.review 目錄放任意 MD 檔引導 review；rules 在符合條件（如改到定價檔）時觸發動作；rules 還能在 PR 描述貼 Slack 連結時比對討論內容
- 自動化設定：開啟 GitHub allow auto-merge、建立要求 status check「test」通過的 branch ruleset，再用留言「auto apply on」「automerge on」啟用自動修復與合併
