## Who Is Making This Request? Agent Auth 101 - Kamil Potrec, Keycard

不要把長期密鑰交給 AI agent，改由閘道在請求當下代為注入短效憑證。

**Why** Agent 非決定性，會自行決定如何使用手上的 token；MCP server 只看到使用者身分，分不出是 Alice 還是 agent 發出的請求，且 PAT、service account 這類憑證難撤銷、權限過大。

**How** 讓 agent 擁有獨立身分（可到 session 層級），用 OAuth 式動態、限定範圍的短效 token 取代靜態金鑰；再把憑證放進 vault，由 gateway 驗證身分與 policy 後注入請求，agent 碰不到憑證，還能即時撤銷、攔截檢查並降權（例如能讀信不能寄信）。

**What** 講者 Kamil Potrec 來自 Keycard，提出 agent 認證需要：agent 身分、委派語意、短效憑證、跨系統聯邦信任、legacy 憑證 broker、policy 與稽核。他也指出 SDK 方案難以全面採用且擋不住 agent 繞過，gateway 則有多一跳延遲、單點目標、TLS 攔截複雜等代價；Keycard 提供控制平面，並釋出 agentbaseline.org 參考實作。

### 重點
- Agent 認證需求清單：獨立於啟動者的 agent 身分、使用者→agent 委派語意、scoped 短效憑證、跨系統聯邦信任、legacy 憑證 broker、policy（哪些動作需人工核准）與稽核
- SDK 方案四大缺點：需全面採用、需覆蓋所有語言、無法改動 Claude Code/Codex 這類現成 agent、修 bug 要追蹤使用處；更關鍵的是 agent 只要能在自己的執行環境取得憑證就有風險
- Gateway 方案優點：憑證移出 agent 環境、每個請求即時檢查所以可立即撤銷、可攔截請求做降權（讀信可、寄信擋）、集中可觀測；代價是多一跳延遲、需強制所有流量經過、成為高價值攻擊目標、TLS 攔截複雜
