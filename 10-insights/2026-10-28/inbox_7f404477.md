## How Anthropic Merges 30,000 Code Changes a Day - Manish Kapur, Sonar & Addy Osmani, Anthropic

AI 寫程式的速度已不是瓶頸，真正的瓶頸是有沒有可信的驗證，才敢讓 agent 的程式碼自動合併。

**Why** 程式產出量暴增，但審查跟不上：CircleCI 分析 2,800 萬個 CI workflow，吞吐量增加約 59%，卻有三成合併嘗試失敗；Sonar 調查中 76% 的開發者認為 AI 程式碼產出速度快到無法驗證。

**How** Anthropic 先讓 Claude 做第一輪審查，並要求它像真實使用者一樣實測（端到端測試、瀏覽器操作、linting）；發現問題時用 hooks 在編輯時分析 diff 並修正 PR。團隊把品味與最佳實踐寫進 CLAUDE.md／AGENTS.md，人只檢視 agent 提供的證據（影片、截圖）。Sonar 主張零信任、多層驗證：確定性層抓 SQL injection 等、agentic 層抓邏輯與意圖問題、供應鏈層抓 CVE 與惡意套件。

**What** Sonar 的 Manish Kapur 與 Anthropic 的 Addy Osmani 在 AI Engineer 對談。Addy 表示 Anthropic 每天合併約 30,000 個程式變更，5 月時約 200，claude.ai 改版約合併 3,000 個 PR；PR 應標註 agent 撰寫，但責任仍在人身上。Sonar 調查：目前 5% 公司使用 software factory，預計升至 34%；Addy 預期多數團隊會是「亮燈工廠中有些暗角」。

### 重點
- Anthropic 每日合併約 30,000 個變更；5 月約 200，claude.ai 改版約 3,000 個 PR；流程：Claude 先審查並實測、hooks 在編輯時修正、人檢視影片／截圖等證據
- 驗證手段：端到端測試、property test、視覺驗證測試；Addy 稱有可靠驗證可讓輸出品質提升 2～3 倍
- Sonar 三層驗證：確定性（SQL injection 等）、agentic 審查（邏輯與意圖）、供應鏈安全（CVE、惡意套件）；數據：CircleCI 吞吐量 +59% 但 3/10 合併失敗，5% 公司已用 software factory
