## Exploits Now Beat Patches: Open Source Security in the AI Era - Patrick Smyth, Chainguard

AI 讓攻擊者更快更強，漏洞被利用的速度已經快過修補速度，防守要從「30 天內修」改成「更快、更少依賴、更早簽章驗證」。

**Why** 依 Mandiant 數據，漏洞從被利用到修補的平均天數，2018–2019 年約為 63 天，如今變成 -7 天（exploit 先於 patch）；供應鏈惡意程式、前沿模型找 zero-day 也讓傳統掃描加 30 天修補的節奏失效。

**How** 講者 Patrick Smyth（Chainguard）建議：套件設 cool down 期、加快 CVE 修補、用 Sigstore/SLSA 簽署並驗證 artifact 與 provenance、保護開發者筆電與 CI/CD；Chainguard 的做法是從原始碼自建並替換 PyPI/npm/Maven 套件、用滾動發行的 Wolfi 發行版每日重建映像並維持極簡。

**What** 講者舉例：一名攻擊者用 Claude Code 攻擊 17 個組織、日本 17 歲高中生用 ChatGPT 外洩約 440 萬筆資料，並提到 Trivy、Axios（上線約 2 小時、60 萬次下載）等供應鏈事件。Chainguard 的 SLA 為已知被利用漏洞 1 天、critical 7 天、其餘 14 天；產品包含 Libraries、Containers、Actions、Agent Skills 與 Athena 零時差聯盟，並稱上游 agent skills 約 5% 為惡意、另有 30–40% 有嚴重安全問題。

### 重點
- Mandiant 數據：漏洞 exploit 對比 patch 的平均時間差由 2018–2019 年的 63 天變為 -7 天，意味 exploit 平均早於 patch
- 新的軟目標：CI/CD、開發者工作站、agent 層與模型投毒；講者稱 cool down 期對惡意套件有效，但開發者筆電常沒有套用
- Chainguard SLA：已知被利用漏洞 1 天、critical 7 天、其餘 14 天（取代 30/60/90 天節奏）；建議 Sigstore 簽署 + SLSA provenance 建立零信任 pipeline；講者估計上游 agent skills 約 5% 為惡意
