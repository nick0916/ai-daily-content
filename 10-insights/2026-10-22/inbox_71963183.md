## v3.59.16 — flag-parsing fixes (--no-color, --no-browser) + AgentDB lock-state fix

修正 RuFlo 三處問題：CLI 旗標 --no-color、--no-browser 失效，以及 AgentDB 鎖定狀態誤判。

**Why** 旗標解析對 kebab-case 與 camelCase 處理不一致，導致旗標被忽略；已死亡但仍在過期門檻內的鎖，會被永遠誤判為其他程序正在寫入。

**How** hooks statusline 改為檢查解析後的 color:false；auth login 改為讀取 browser:false；inspectAgentdbLock() 新增 recent 狀態，區分近期死鎖與活躍寫入者，並修正 mtime 與 Date.now() 漂移造成的負值年齡。

**What** 對應 PR #4387、#4388、#4389；agentdb-lock-guard 測試 19/19 通過。@claude-flow/memory@3.0.9 在本次發布前單獨發布，以通過 leaf-version 審計。

### 重點
- hooks statusline 現在也檢查 color:false，修正 --no-color 失效（#4387）
- auth login 讀取 browser:false，修正 --no-browser 在無頭主機上的手動登入流程（#4388）
- AgentDB 鎖新增 recent 狀態，已死亡且未過期的鎖不再被無限期視為活躍寫入（#4389）

What's new 
 
 fix(hooks): honor --no-color in hooks statusline ( #4387 ) — the parser stores --no-color as color: false , not noColor ; the statusline command now checks for that too. 
 fix(auth): honor --no-browser for auth login ( #4388 ) — same kebab-vs-camelCase parsing gap ( browser: false ), fixing the copy-paste manual sign-in flow on hosts isProbablyHeadless() doesn't recognize. 
 fix(memory): distinguish recent dead locks from live writers ( #4389 ) — inspectAgentdbLock() now has a recent state distinct from live : a lock holder that's dead but the lock is still younger than the stale threshold no longer gets treated as "another process is writing this database, retry when it finishes" forever. Also fixes a possible negative age from filesystem mtime/ Date.now() drift.
