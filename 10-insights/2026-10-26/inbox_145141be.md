## Agents That Self Improve While You Sleep - Fuad Ali, Arize AI

讓一個監控用的 AI 讀別的 AI 的執行紀錄，自動找出錯誤、寫修正、驗證後再交給人審核。

**Why** Agent 行為不確定、數量又多，沒有人讀得完所有 trace，凌晨出事才被叫醒也來不及。

**How** 流程為 trace → Signal 定期讀 trace 並分群問題 → 存成 dataset → 產生 eval → 連 GitHub 讀原始碼並開 PR → 用 experiment 重跑失敗案例驗證修正 → 人審核後合併，所有結果再回饋給下一輪。

**What** Arize 的 Signal（受管 agent，預設每 6 小時掃一次）。Demo 的 Wonder Toys 購物 agent 被植入 bug：商品類別 slug 為小寫連字號，LLM 卻傳入 title case，導致重複搜尋、延遲高達 14–17 秒。Signal 花 6 分鐘找到根因並開 PR，experiment 通過率 88.9%。講者建議人只留在審 PR、決定 dataset 收錄、設計 eval 的品味、低信心結果的標註。

### 重點
- 閉環步驟：trace → Signal 分群 → failure dataset → eval → 修正 PR → experiment 驗證 → 人審核合併，每步產出都成為下一輪 context
- Demo bug 為類別 slug 大小寫不一致，造成 3 次連續 LLM 呼叫與 14–17 秒延遲；修正後在失敗 dataset 上重跑，通過率 88.9%
- 人類高槓桿點：審 PR、決定哪些失敗案例進 dataset、設計 eval 的品味、處理低信心分數；用 decision model 的信心分數自動分流到標註佇列
