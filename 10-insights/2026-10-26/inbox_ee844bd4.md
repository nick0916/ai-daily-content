## Build Your Own Team of Managed Agents - Jack Wotherspoon, Google DeepMind

用一個 API 呼叫就能在雲端沙箱跑一個完整的 coding agent，不用自己管容器與 harness。

**Why** 自己架雲端 agent 要處理容器或 VM、harness 工程、網路與防火牆、資安，而且個人電腦跑 agent 難以擴展、也無法與同事或應用共享設定。

**How** 在 Gemini API 的 Interactions API 呼叫 Antigravity agent 並設 `environment=remote`，Google 就會建立沙箱。Interaction（對話）與 environment（檔案系統）分開保存，因此可讓多個 agent 共用同一個 environment、各自使用全新的 context；密鑰由 proxy 注入，沙箱內只有佔位 token。

**What** Gemini managed agents 包含 harness、environment、skills、credentials、triggers 五個核心元件，可上傳 agents.md、skills 與 GitHub repo，支援遠端 MCP 與自訂函式，並可用 agents.create 儲存設定。Demo 用三個 agent 依序處理 SEC 文件研究、量化分析與報告。講者稱前一天發布了 Gemini 4 Argon（output 與 input、thinking 共用 1M token 額度），這部分為講者說法，原文未提供其他細節。

### 重點
- Interactions（對話狀態）與 environment（沙箱檔案系統）是兩個獨立的 server 端原語，可用同一 environment ID 串接多個全新 context 的 agent，做 multi-agent 流程
- 安全設計：沙箱內只放佔位 token，真正的 GitHub token 由 proxy 在呼叫對應 API 時才注入，避免 agent 取得祕密
- 五大元件：harness（Antigravity）、environment、skills、credentials、triggers（可排程，例如開盤前自動分析並透過 webhook 發 Slack）
