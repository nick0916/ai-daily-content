## I Made a Fruit Fly Review My Code - Nick Nisi, WorkOS

用果蠅大腦的神經連接圖來判斷程式碼變更好不好，探討 PR 審查的瓶頸與解法。

**Why** 程式碼產出越來越快，CI、linter 與 AI 審查工具都已就位，卻卡在人工審查，講者自稱成了瓶頸。

**How** 以小模型把 diff 問 30 個無偏見問題轉成「氣味」輸入果蠅 connectome，並用測試結果以甜（獎勵）或苦（懲罰）訓練其記憶，再依牠是否伸舌頭投票。

**What** 講者 Nick Nisi（WorkOS）指出果蠅在其測試中約 88% 判對，現場三題對兩題；但它說不出為什麼，也無法提出修改。他主張的流程是：團隊維護的 review skill → 分類器 → 自動審查工具（Greptile、CodeRabbit、Qodo）→ 失敗才升級給人，並要求附上截圖、測試輸出等驗證證據，Demo 網址為 fruitfly.review。

### 重點
- 果蠅 connectome：約 176,000 神經元、630 萬連結、超過 1.25 億突觸；除用來存記憶的一小部分神經元外未改動；移除記憶後行為失常，說明判斷確實來自果蠅
- 準確率：測試約 88%，較難的測試中明顯錯誤案例約 96%、貌似合理的錯誤約 98% 被要求修改；現場 live demo 則無法區分
- 審查升級流程：團隊 review skill → 輕量分類器（複雜度與風險）→ 自動審查工具 → 任一失敗才交給人；人的角色轉為理解變更「為什麼」，並以截圖、測試結果等取得驗證
