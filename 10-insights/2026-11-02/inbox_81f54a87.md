## Inside Figma’s PM OS: skills, agents, and Auto XP

把 PM 的重複雜務與瑣碎判斷寫成可重用的 AI 技能包，讓 AI 當 PM 的分身去跑。

**Why** 大公司裡 PM 身兼太多角色，有些工作（通知客服、會議紀錄、找 code owner）做不好或根本沒做，Slack 又雜亂到難以掌握重點。

**How** 用一個基本 repo：agent.md 定義行為、多個 skill 定義何時觸發與做什麼、啟動時檢查版本的 command hook；個人工作區是 subrepo，可私下寫回。實驗自動化則用三個由 Slack 觸發的 Cursor automation，分別叫 data scientist、UX writing、engineer agent，上線前人工只審一次，實驗結束後再由 webhook 觸發結果分析。

**What** Figma 內部的 PM OS 有 31 個 skill（如 what's up、找人、spec、coaching、build artifact、FigJam builder），約 60–70 位 PM 使用，最初用 Claude Code，現在主要用 Codex（含瀏覽器 bug bash）。另有 Auto XP：目前有 5 個並行實驗，首次實驗就找到大贏。講者也展示用 Jev（快又便宜的小模型）做即時寫作編輯器，停筆就檢查缺漏與待佐證論述，並從資料庫撈訪談引文。

### 重點
- PM OS 是簡單 repo：agent.md + 31 個 skills + 啟動時檢查更新的 hook；個人 workspace 為 subrepo，讓 GitHub 新手也能私下寫回；隨模型變強持續刪減不再需要的 skill
- Auto XP 以 3 個 Slack 觸發的 Cursor automation（data scientist / UX writing / engineer agent）串接，人只在上線前審一次，結束後用 webhook 觸發分析；目前 5 個並行實驗，首個實驗即大勝
- Codex 瀏覽器操作用於 bug bash：依 FigJam 測試腳本跑固定帳號流程，找到 1000 個 emoji 會讓文字框壞掉、團隊名稱 a/an 文法錯誤等人工難發現的細節
