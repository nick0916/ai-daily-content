## AI Writes Code Faster Than Your Team Can Review It - Andrew Norrish, Sourcegraph

AI 寫程式的速度已超過人類 code review 的承受力，瓶頸從寫程式移到審查與事故處理。

**Why** AI 讓 PR 數量與大小暴增，開發者既不完全信任 AI 程式碼、又沒時間逐一驗證，沒被人看過的程式碼上線後引發的事故落到 SRE 與平台團隊頭上，而且缺乏 context 難以排查。

**How** 講者主張把 AI 用在範圍明確、context 完整的領域（漏洞修補、安全掃描、大規模遷移），並用 code search 與 code graph 作為 context engine，涵蓋調查、預防（對風險 commit 設監控告警）與修復（跨 repo 批次修改）三類 SRE 工作。

**What** Sourcegraph 現場工程總監 Andrew Norrish 引用業界估計：合併的 PR 數量接近兩倍、單一 PR 大小超過兩倍、review 時間接近兩倍，2027 年約三分之二程式碼由 AI 撰寫。他舉了三個案例：內部以 HackerOne webhook 加 agentic search 做資安報告分流、一家擁有 5000 多名開發者的客戶用 root cause 分析 agent 從 log 追到 commit 並可回滾、另一客戶用唯讀 codefinder agent 跨數百個歷史分支跑 code review agent 的 eval。

### 重點
- 引用的業界估計：合併 PR 數接近兩倍、PR 大小超過兩倍、review 時間接近兩倍，且幾乎所有開發者表示不完全信任 AI 程式碼
- AI 的有效戰場是範圍明確的任務（漏洞修補、安全掃描、大規模遷移），SRE/平台團隊本來就在這類半自動流程上，既是 AI 品質的指標，也是受益最大的團隊
- 三個案例：HackerOne webhook 安全分流、5000+ 開發者客戶的事故 root cause agent（定位部署分支 → git 歷史找 commit → 回滾或轉交）、跨數百歷史分支的 code review agent eval
