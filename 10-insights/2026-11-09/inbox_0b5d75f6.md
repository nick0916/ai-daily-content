## How One Founder Manages 20 AI Coding Agents at Once - Ryan Carson, Untangle

把管理工程師的方法搬到管理 AI agent：一個從不寫程式的「經理 session」帶約 20 個「builder session」，人只負責看影片驗收。

**Why** 講者 Ryan Carson（Untangle 創辦人，做離婚法務的 AI 助理）認為管理 agent 與管理人很像，瓶頸在於人能多快理解並指揮經理 agent，同時 agent 非確定性、不能全靠它自己記得巡檢。

**How** 經理 agent 從 Linear 的 ticket 板依相依性派工，每張 ticket 對應一個 PR；用自動化腳本強迫經理每 15 分鐘讀過所有子 session 並推進；每個 builder 最多與 review agent 循環 3 次，仍有重要 bug 才往上交給經理、再交給人；另由 QA agent 以 builder 的子 session 執行，builder 錄下功能操作影片並產出 test 綠／紅結果；另設 merge queue manager 協調資料庫 migration 編號等衝突，並搭配 GitHub merge queue。

**What** 實作在 Devin（字幕作 Devon），經理 session 並行管理約 5～25 個 builder，講者估計約 25 個是極限；人必須親自看影片再放行，並主張不要在本機開發、要用雲端 agent。招募方面不做預先面談，改要求候選人交 45 分鐘左右的全螢幕錄影（自己做一個功能 PR），由排名 agent 排序，前 5 名付固定費用做 16 小時的實作專案，最後才與決選者通話。

### 重點
- 經理 session 不寫程式、只對話；約 5～25 個 builder 並行；用自動化每 15 分鐘巡檢所有子 session，不信任 agent 自己記得
- 品質關卡：review 最多 3 輪、QA agent 為 builder 的子 session、builder 錄影並給綠／紅測試結果，人必須親自看影片；另設 merge queue manager 處理 migration 編號衝突
- 招募流程：45 分鐘螢幕錄影 → 排名 agent 排序 → 前 5 名付費做 16 小時實作專案 → 決選者才通話，講者承認第一次不信任排名結果反而錯過第一名
