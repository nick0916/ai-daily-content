## What Your Coding Agent Can't See in the Code - Tom Moor, Linear

把「為什麼要做這件事」的脈絡從需求進來一路帶到 review，讓 agent 改的不只是正確、而是適合整個產品。

**Why** 程式碼已不是瓶頸，真正的失敗是無法維持產品一致性；agent 只讀程式碼，看不到意圖、過去決策、取捨、其他進行中工作與負責人。

**How** 先用 triage agent 自動分流並調查，把客戶資訊、堆疊追蹤、相關歷史寫進 issue 當基礎脈絡；實作端強調驗證與 CI 失敗回饋；review agent 再帶入原始意圖、過往 revert／事故、相關議題與完整 agent session；最後每日自動化把可行動的教訓萃取回 agents.md 或文件。

**What** Linear 的 Tom Moor 分享其內部做法，多數已在產品中提供。例子包括 review agent 找到 6–7 個月前因 DB transaction 長開造成事故風險的變更（Codex 未抓到）、攔下一年前已被否決的 UI 圖示重新出現。重點是減少解錯問題與重工，讓人的判斷變成下一輪的 context。

### 重點
- agent 看程式碼看不到的是：意圖、過去決策與取捨、其他進行中工作、決策負責人、近期 revert 等風險
- triage agent 自動標記、指派、合併重複、調查並重現 bug，把客戶價值、堆疊追蹤、Datadog 日誌與相關議題寫入 issue，作為後續 agent 的基礎脈絡
- review agent 使用產品歷史（revert、事故、被否決的設計）做審查，抓到標準 review 工具沒發現的問題
- 每日自動化掃描已合併變更與 PR 留言，萃取教訓回寫 agents.md／文件，並要避免它無限膨脹
