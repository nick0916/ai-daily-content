## The One Thing Every AI Agent Framework Agrees On - Mislav Ivanda, Daytona

先決定 agent 的程式碼要在哪裡執行（執行邊界），再選框架，因為框架可以換，邊界換不了。

**Why** Agent 一定會需要執行程式或 shell，若在本機或與應用程式同一環境執行，一旦模型或某一步被入侵，整個應用都會受影響。

**How** 比較三種隔離：本機允許清單加核准提示、內嵌引擎（V8、QuickJS，但工具呼叫仍在主機上執行）、獨立 VM／沙盒（透過 API 控制生命週期，被入侵時直接丟棄重建）。

**What** Daytona 的 Mislav Ivanda 整合各框架後發現，不論框架理念多不同，底層都只是「建立沙盒、執行、刪除」三步。他舉例：2026 年 4 月 CrewAI 移除本機 code interpreter 並改指向沙盒服務；AG2 淘汰舊本機執行器改用 sandbox code tool；Claude Agent SDK 預設沙盒（僅 bash 層級）；OpenAI Agents SDK 有 sandbox agent。他的結論是「框架是意見，邊界是承諾」，建議先定義自己控制的執行介面，其餘（框架、模型、提示詞、缺少的功能、沙盒供應商）都可替換；只有 durable execution 較難複製。講者為沙盒供應商 Daytona 員工，立場帶有商業利益。

### 重點
- 三種隔離層級：本機允許清單（python -c 即可開 socket、改檔案）、內嵌 V8/QuickJS（膠水碼隔離但工具呼叫仍在主機執行）、獨立 VM（被入侵只需丟棄重建）
- 框架趨勢：CrewAI 於 2026 年 4 月移除本機 code interpreter、AG2 淘汰本機執行器，皆轉向沙盒；各框架對 agent 定義不同，但沙盒整合都是建立／執行／刪除三行
- 選型心法：框架、模型、提示詞、評估、追蹤、記憶、沙盒供應商都可替換，真正難改的是「執行姿態」，應先於框架決定，並以自己控制的介面包住
