## Why One AI Agent Isn’t Enough (And How to Run 1,000) - CJ Avilla & Harrison Stall, Anthropic

Anthropic 技術團隊成員 CJ Avilla 與 Harrison 在 AI Engineer 場次中，用軟體史說明為何需要多 agent 協作，並介紹 Claude Managed Agents 的新功能 flows。開場對比兩種模式：Ken Thompson 一人在一個月內寫出 Unix，靠的是 conceptual integrity；IBM OS/360 估計約需 5,000 man-years、投入多達 1,000 名工程師，Fred Brooks 因此寫下《The Mythical Man-Month》，提出以一位 surgeon 搭配專家的外科團隊結構。接著以 Linux 為例：Linux 7.2 歷時九週，有 2,600 多位開發者、300 多家公司貢獻。1998 年 Linus 因所有 patch 都直接寄給他而崩潰，約 2002 年改為由受信任的 maintainer 分層審查，只把例外往上送；圖中星狀結構有 36 個貢獻者直連中心，網狀分層結構每層最多約 4 人。他們把這點類比給管理大量 agent 與 PR 的人：人容易成為瓶頸。flows 於演講前的星期五發表，屬於 4 月推出的 Claude Managed Agents 產品，讓 Claude 自行編排整個多 agent 拓撲，延續 Claude Code 中 dynamic workflows（底層使用 JavaScript engine）的概念。場次含動手實作，並提供開發者額度。原文在 flows 技術細節處截斷。
