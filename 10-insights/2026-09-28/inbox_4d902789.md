## What product looks like when coding is solved | Geoff Charles (Ramp CPO)

Ramp CPO Geoff Charles 以賽車比喻切入：車手只佔比賽影響的約 15%，贏的關鍵是移除系統瓶頸，如同換胎從 1950 年代的 67 秒降到 1.8 秒，且 F1 每年約 90% 的零件會更換。他主張 AI 讓寫程式不再是瓶頸，但瓶頸只是轉移到 PM 這一側（定義、協作、協調、測試、發布），因此必須為自己的流程投資「工廠」。他拆成 identify、define、build 等步驟（原文截斷，只涵蓋到 build）：在 identify 階段，一百萬 token 的 context 還不到 Ramp Gong 逐字稿的 0.5%，所以他們先做出 hate channel 與 podcast，再重做成整合 ETL、向量搜尋與分群的 customer insight agent，且資料可追溯以決定該訪談哪些客戶。define 階段使用自建的 Glass agent，連接 Snowflake、使用者研究、產品策略、spec 規範與程式碼庫，讓 PM 不必打擾工程師就能確認可行性並做出符合設計系統的 prototype。build 階段的自建 coding agent Inspect 在 Slack 內運作，約 5 秒內啟動並回傳部署預覽；累計一百萬個 session，75% 的 PR 由 Inspect 產生，上個月有上千個 PR 來自非工程師。給工程團隊的交付物不是長 spec，而是量化加質化資料、可供 coding agent 使用的需求，以及能啟發他們的 prototype。
