## The AI factory playbook for engineering teams

把團隊的 AI coding agent 集中到雲端、在公開頻道運作並持續量測與自我改進，形成「軟體工廠」。

**Why** 每位工程師在本機各用各的 agent，管理者看不到速度、品質與成本，也無法系統化改進。

**How** 工廠以程式碼定義（repos、MCP servers、設定與多個 agent）；任務從 Slack 觸發，自動開 Linear issue、實作、建 PR、用 computer use 錄影做 QA。所有執行用 LLM-as-judge 評分，再由 observer agent 累積約 20–25 次失敗後提出修改工廠定義的建議，並能用過往任務重播不同模型配置以比較成本與品質。

**What** Warp CEO Zach Lloyd 展示其內部工廠「Wilson」：指標包含每個 PR 的人類互動次數、agent 成本（調整模型配置後下降）；提到 kickoff 到 PR 約 35 分鐘、PR 到首次人類審查約 3.5 小時，人類是瓶頸；上月 PR 超過 2,000 個。他也示範以 Figma／Granola／GOG CLI 等 MCP 搭配 coding agent 做簡報與銷售研究。

### 重點
- 工廠流程：Slack 觸發 → Linear issue → 實作 → PR → computer use 錄影 QA，全程公開；工廠本身以程式碼定義，可版本化、可重播
- 指標：每 PR 的人類互動次數、agent 成本（模型是最大槓桿）、LLM-as-judge 評分；observer agent 需約 20–25 筆失敗樣本才提出改進，避免單點過度修正
- 瓶頸數據：kickoff 到 PR 約 35 分鐘，但 PR 到首次人類審查約 3.5 小時；code review 變成風險管理，低風險 PR 可由 agent 預審
