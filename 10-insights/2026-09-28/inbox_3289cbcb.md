## Shipping Enterprise AI Agents with the CPOs of Rubrik, Glean, and Harvey

三家企業 AI 產品的 CPO 分享如何把 agent 做到可上線：核心是 human-in-the-loop 核准計畫、確定性執行、與豐富的情境資料。

**Why** 企業客戶要 agent 動手做事，但出錯會直接傷害信任（資安還原、法律產出、寫入 CRM），因此要在自動化與安全之間取得平衡。

**How** Rubrik 讓 LLM 產生計畫、但還原計畫本身是確定性且可解釋，由人類核准後才執行；Glean 把離線處理的組織脈絡以單一 MCP server 提供給 Claude Code、Cursor、Codex 等外部工具；Harvey 提供自然語言與確定性兩種 agent builder，並派「律師出身」的 legal engineers 與客戶共建流程。

**What** Rubrik 的 agent「Ruby」從 RAG 問答進化為可做容量規劃等的 agentic 平台，目標是讓客戶只定義意圖；Glean 表示經 Claude／Cursor／Codex 的使用是成長最快的部分，並展示以 Gong 通話自動更新 Salesforce 的部門級 agent；Harvey 在 Amlaw 100 逾 60%、有約 180 位 legal engineers，客戶問題已從「要不要用」轉為「如何協作、驗證與指導 agent 計畫」。

### 重點
- Rubrik 的 Ruby 由 RAG 進化為 agentic：LLM 生成計畫、還原執行保持確定性與可解釋，人類核准計畫（human-in-the-loop 在批准 plan）
- Glean 以單一 MCP server 對外提供離線預處理的組織脈絡，與執行期 MCP 即時抓取互補；經 Claude/Cursor/Codex 的使用成長快於自家 UI
- Harvey 配 legal engineers（約 180 位，多為 8–10 年資歷的律師）協助客戶客製 agent，並提供自然語言與確定性兩種 builder
