## Don't Vibe Code Your Agent Infrastructure - Akshat Bubna, Modal

Agent 要的不是自己 vibe code 出來的環境，而是可靠、能彈性伸縮的運算、儲存與網路基礎元件。

**Why** Agent 的資源用量變化極大、會存取敏感資料、還需要長時間保存狀態，自己寫沙箱平台在可靠性、安全與規模上都容易出事。

**How** 把 harness（agent loop）與實際執行工具的 sandbox 分離，一個 sandbox 內跑多個容器含 sidecar，搭配快照、共享 volume、細到路徑層級的網路控管與不讓 agent 看到的憑證注入，並提供可觀測性給 agent 自己讀。

**What** Modal CTO 演講，客戶包含 Hebia（每個試算表儲存格由一個 agent 支撐）、Ramp Inspect、Basis；數據：每週約 2,000 萬個 snapshot、每日處理約 8 PB、每週建立約 260 萬個 volume，個人助理類負載需每秒建立 10,000 個 sandbox、約百萬個並行、存活 2–3 分鐘且需 1 秒內可互動。

### 重點
- Ramp Inspect 的 sandbox CPU/記憶體用量變異大，若依峰值配置每個需約 15 核 CPU 與 15 GB RAM，經濟上不合理，需彈性配置、按用量付費
- 網域 allowlist 不夠，用戶需要路徑層級控制，常見做法是自寫輕量 proxy 當 sidecar；憑證應注入使 agent 看不到
- 「腦（harness）與手（sandbox）分離」，agent 動態開環境、快照當 artifact，是 pets→cattle 之後的下一步演進
