## Stop Giving Your AI Agents API Keys - Kim Maida, Keycard & Mason Egger, Temporal

不要把一把萬用 API key 交給 agent，改成每次工具呼叫都換發短效、限縮權限且能追溯到使用者與 agent 的 token。

**Why** API key 無法歸屬到使用者或 agent 身分，agent 擁有 key 的全部權限，而人類每步把關既會出錯、許多 agent 又自主運行。

**How** 使用 OAuth 2 擴充的 Token Exchange 標準（2020 年即有）：使用者登入並同意部分 scope，agent 以自身憑證加上使用者 subject token 向 Keycard STS 換取僅限 MCP server 的短效 token，MCP server 再做第二跳換取 ledger API 的 token，並由 policy 評估；Temporal 則提供 durable execution，讓 agent 失敗後重放狀態而不重打 LLM，secrets 以 interceptor 注入、不寫進 event history。

**What** AI Engineer NYC 工作坊（Keycard 的 Kim Maida 與 Temporal 的 Mason Egger），用 expense desk agent（LangChain agent + expense MCP server + ledger API）示範：agent 可自行核准 $50 以下費用，超過則需人審，且 agent 不能核准自己提交的費用；稽核紀錄可追溯跨兩跳的 delegation chain。 （原文被截斷，結尾部分未見。）

### 重點
- Token Exchange 流程：user subject token → agent 向 Keycard STS 換 MCP token（每次工具呼叫一枚）→ MCP server 二跳換 ledger API token；token 數分鐘過期且不儲存
- Demo 結果：agent 身分可核准 <$50 費用，超過限額為 pending 需人審，且無法核准自己提交的費用；稽核紀錄以 session 串起兩跳
- Temporal：工作流程崩潰後重啟 worker 會重建狀態、不重做 LLM 呼叫；Keycard interceptor 讓憑證不進 event history，另可用 payload encoder 加密
