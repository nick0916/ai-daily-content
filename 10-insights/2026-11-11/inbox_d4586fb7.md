## Agents Made Code Free. Maintaining It Didn't Get Cheaper. - Dmitry Buykin, Maersk

agent 讓寫程式變便宜，但維護沒變便宜；作者用每週小規模清理與回饋迴圈取代一次性大砍。

**Why** 程式碼量增長速度超過人能審查的範圍，作者曾一次砍光重寫、遺失有用部分，之後又長回來；他自己也因逐一審查而 burnout。

**How** 以六個問題為框架：用 lint 與帳本檢查 prompt 的一致性、重複出現的 agent 路徑才轉成程式碼、由 runtime 決定模型看到的 context（用 handle 取代全文）、寫入前多道檢查與 journal 保證只執行一次、用第二個 agent 依檢查表獨立驗證，並以真實任務重播證據判斷分支是否保留。

**What** Maersk 的 Dmitry Buykin 分享在 110 國、約 1 萬個 prompt 情境的系統維護經驗，其中約四分之三是 prompt。新檢查規則上線前會重放數千個過往 session（觸發不到 1%）；一個 backlog 看似大多已覆蓋，實際只有約四分之一真正能關閉；並附 18 個自我檢核問題。

### 重點
- prompt 也需要工程化：為 prompt 做 lint、帳本與漂移檢查；重複出現且跨國一致的 agent 路徑才轉成 code
- runtime 決定模型看到的 context，模型只傳 handle，降低模型因看見資訊而亂發動作
- 驗證證據分級：真實任務重播最高；第二個 agent 用檢查表獨立審查；一個 backlog 約四分之一才真正可關閉
