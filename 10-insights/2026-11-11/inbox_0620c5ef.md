## 225,000 Lines of Tests, Written and Merged by Agents - Kush Agrawal, Duolingo

讓 agent 自動挑檔案、寫單元測試、修 CI、找人審查，把 iOS 測試覆蓋率補起來。

**Why** 當 agent 讓寫程式變快，瓶頸轉為驗證；單元測試便宜又能當 agent 的護欄，但 Duolingo iOS 的 MVVM 部分覆蓋率只有約 9%。

**How** 用 Temporal 編排 workflow，Claude Code 當寫測試的 agent，S3 存共享狀態；選檔腳本依檔案類型打分（view model、repository、data source 加權 2.5 倍），PR 生命週期 workflow 每隔幾小時對每個 PR 採取一個動作（CI 失敗最多修 5 次、git blame 找審查者、被拒則 30 天冷卻）。品質把關有三層：非測試檔被改就關閉、AI code review 的 P0 留言由 agent 處理、LLM-as-judge 擋掉改 production code、刪改測試與長等待。

**What** 約 8 個月內合併 700 多個測試 PR、約 22.5 萬行測試；MVVM 覆蓋率 9%→59%，整體 11%→24%。LLM judge 審了約 200 個 PR、退回 73 個；早期本機驗證合併率約 50%。每個 PR 都經人類核准。

### 重點
- 成果：700+ 個測試 PR、約 225,000 行測試；MVVM 覆蓋率 9%→59%，整體 11%→24%
- agent 抄捷徑的對策：非測試檔被改直接關閉、AI review P0 自動處理、LLM judge 退回 73 個 PR
- agent 改在 Mac runner 執行以便本機 build 與 lint（原本 13.6% 的 PR 因 lint 失敗）
