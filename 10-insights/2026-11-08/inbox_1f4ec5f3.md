## Your Coding Agent Can't Undo Its Own Mistakes - Tanmay Sah & Dolly Sah

讓 coding agent 在出錯時真的能復原，而不只是重試，並把「可復原性」當成自我演化改動的准入條件。

**Why** agent 能完成任務不代表能從失敗中復原；git revert 只能還原 repo 變更，還原不了外部 API 呼叫、部署、資料庫寫入或 agent 自身 harness 的狀態，盲目重試甚至會產生重複副作用。

**How** Evo-Undo 演算法在套用變更前先擷取原始狀態見證（state witness），套用變更並執行復原計畫後，由獨立 verifier 驗證原始狀態是否真的還原；只有同時滿足能力提升與可復原性的改動才被採納。

**What** Undo-Bench 以 2880 組成對試驗評估：正常執行成功率 84%，注入失敗後僅 47% 成功復原；單純重試在 54% 的試驗產生重複副作用。Evo-Undo 實驗中 600 個自我演化任務有 478 個提升能力，其中 197 個（約 42%）有復原缺陷；提供精確狀態資訊使復原從 0 提升到 38/48，擴充復原語言後從 0 提升到 142/143，整體復原 180/197（約 92%），可採納的改進從 281 增至 461。

### 重點
- Undo-Bench：2880 組成對試驗，正常成功率 84%，注入失敗後僅 47% 成功復原；單純重試在 54% 的試驗造成重複副作用（如重複建立 ticket）
- Evo-Undo：600 個自我演化任務中 478 個提升能力，其中 197 個（約 42%）有復原缺陷；兩個瓶頸為狀態 grounding（0→38/48）與復原表達力（0→142/143）
- 擴充復原語言後 197 個缺陷中復原 180 個（約 92%），可採納改進由 281 增至 461/600；失敗發生在變更前、中、後需用不同策略（重試／復原／補償動作／升級給人）
