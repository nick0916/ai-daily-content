## How Stanford Teaches AI-Native Engineering — Mihail Eric, Monaco

史丹佛 AI 原生工程課程的講師，談程式碼代理時代工程師該學什麼，以及在 Monaco 實際驗證了哪些。

**Why** 學生已能用代理一次 prompt 完成去年的作業，課程與團隊都得重新定義什麼才是必學能力。

**How** 課程把作業改成貢獻開源專案，由維護者審查學生的 patch；Monaco 則以「買來學習、自建來留存」決定自建或採購。

**What** Mihail Eric 教授 Stanford CS146S（The Modern Software Developer）並領導 Monaco 的 AI。Monaco 評估後繼續用 Devin 做 code review，但自建代理工作區與 Hal（可調查故障並開 PR）。所附 Faros 研究指出，高 AI 採用率團隊合併的 PR 多 98%，PR 審查時間卻長 91%。

### 重點
- 作業設計：去年九個作業加 capstone 可被代理一次 prompt 解掉，今年改為向開源專案貢獻，由維護者審查 patch
- Monaco 決策原則：「You buy to learn, and you build to keep」；code review 繼續用 Devin，代理工作區自建
- Faros 研究：高 AI 採用團隊合併 PR 多 98%，PR 審查時間長 91%，code review 成為瓶頸
